**대상:** `src/prestudy/` 수업 동반 노트 생성기  
**구현 담당:** Antigravity

## 목표

- 일반적인 족첵·써머리 조합은 제출 후 5분 이내에 HTML을 만든다.
- 텍스트 레이어가 부족하거나 시각 확인이 필요한 PDF도 제출 후 10분 이내에 결과를 만든다.
- OpenAI API나 API 키를 추가하지 않고, 기존 ChatGPT 구독 로그인 기반 `codex exec`만 사용한다.
- 속도를 위해 학습 내용의 핵심 범위나 페이지 기준을 임의로 누락하지 않는다.
- 여러 작업을 동시에 제출해도 먼저 제출된 한 작업이 여러 Codex 슬롯을 독점하지 않게 한다.

## 확정 구현 방향

### 1. 기본 경로를 Codex 1회 직접 합성으로 변경

`src/prestudy/service.py`의 기본 생성 경로에서는 학습가이드 캐시만 재사용하고, 이번 수업의 족첵·강의자료·써머리를 각각 `SourceDigest`로 만들지 않는다.

1. PDF 텍스트를 로컬에서 페이지 구분과 함께 한 번만 추출한다.
2. 공통 학습가이드는 기존 캐시된 digest를 사용한다.
3. 족첵을 최우선, 선택한 강의자료를 페이지 기준, 써머리를 보조 근거로 하는 원문 컨텍스트를 구성한다.
4. 이 컨텍스트와 학습가이드 digest를 `gpt-5.6-luna`, `low` 추론 강도의 단일 `codex exec`에 전달해 곧바로 `StudyGuide`를 만든다.
5. 생성된 `StudyGuide`에 기존 `align_lecture_flow_to_material()`과 HTML 렌더러를 그대로 적용한다.

새 메서드는 예를 들어 `CodexStudyEngine.synthesize_from_sources(...)`로 두고, 기존 `analyze_source()`와 `synthesize()`는 호환 및 진단용 legacy 경로로 보존한다.

이 변경은 일반 작업의 AI 호출을 3회에서 1회로 줄인다. 최근 최종 합성 호출이 3분 48초~5분 40초였고 SUMMED의 유사한 단일 호출이 약 3분이었으므로, 일반 5분 목표에 가장 직접적인 개선이다. 입력 원문을 한 번만 보내므로 기존의 개별 분석 후 재합성보다 전체 토큰도 줄어든다.

### 2. 텍스트 추출 캐시 추가

- 파일 내용 SHA-256과 추출기 버전을 키로 페이지별 텍스트를 캐시한다.
- 반복 머리글·바닥글과 연속 공백만 제거하고, 의학 용어와 본문은 요약하거나 잘라내지 않는다.
- 빈 페이지와 글자가 깨진 페이지를 기록해 직접 합성 프롬프트에 전달한다.
- 같은 파일 재실행에서는 PDF 복사와 `pypdf` 추출을 다시 하지 않는다.
- 캐시는 `max_entries` 또는 용량 정리 정책을 둬 무한히 증가하지 않게 한다.

### 3. 어려운 PDF도 같은 1회 호출 안에서 처리

- 페이지별 글자 수가 지나치게 적거나 깨진 문자 비율이 높은 PDF를 `visual_required`로 표시한다.
- 단일 직접 합성 호출의 작업 폴더에는 원본 PDF와 추출본을 함께 둔다.
- Codex에는 추출본을 우선 사용하고, `visual_required` 페이지나 표·그림·색 강조가 필요한 페이지만 시각 확인하도록 지시한다.
- 써머리를 별도의 시각 분석 호출로 보내지 않는다. 족첵 또는 선택한 강의자료가 페이지 기준이며, 써머리는 보조 자료다.

최근 자료 중 46MB 족첵도 추출 텍스트는 약 16KB였고, 일부 써머리는 텍스트가 0.1KB라 시각 확인이 필요했다. 어려운 자료에서만 선택적으로 이미지 확인을 허용해야 한다.

### 4. 제출 시각부터 10분 전체 제한 적용

현재 10분 제한은 개별 Codex 프로세스에만 적용돼 큐 대기와 후속 합성을 포함하지 않는다. 다음처럼 전체 작업 예산으로 바꾼다.

- 작업 제출 시 `deadline_at = created_at + 10분`을 기록한다.
- Codex 슬롯 획득 후 남은 시간을 계산해 subprocess timeout으로 전달한다.
- 단일 AI 호출의 권장 소프트 제한은 8분이며, 렌더링과 저장을 위해 최소 1분을 남긴다.
- 9분까지 유효한 구조화 결과가 없으면 페이지별 추출 텍스트와 메타데이터로 `간이 노트` HTML을 로컬 생성한다. 이 파일에는 AI 정리가 완료되지 않았음을 분명히 표시하고, 재시도 버튼을 제공한다.
- 모델 혼잡이나 timeout 뒤에 또 다른 긴 모델 호출을 순차 실행하지 않는다. 용량 오류의 즉시 대체 모델 전환만 남은 시간 안에서 한 번 허용한다.

10분 이내 ‘결과’를 보장하려면 timeout 시 실패 화면만 내는 것으로는 부족하므로 간이 노트 fallback이 필요하다.

### 5. 동시 작업 공정성 개선

- 직접 합성 1회 구조가 적용되면 작업 하나가 동시에 여러 Codex 슬롯을 점유하지 않는다.
- 기본 `PRESTUDY_JOB_WORKERS=3`, `PRESTUDY_CODEX_CONCURRENCY=3`은 우선 유지한다.
- 4건 동시 제출 시 네 번째 작업은 첫 번째 합성이 끝난 뒤 시작되어 보통 6~10분 내 완료된다.
- 실제 측정에서 네 번째 작업이 계속 10분을 넘으면 그때 동시 호출을 4로 올려 비교한다. 먼저 4로 올리면 모델 혼잡과 구독 사용량 경쟁으로 개별 호출이 오히려 느려질 수 있다.

## 진행 표시 변경

백엔드 이벤트에 다음 시간을 별도로 기록한다.

- 큐 대기
- PDF 텍스트 추출
- Codex 슬롯 대기
- Codex 직접 합성
- HTML 렌더링
- Drive 저장
- 전체 경과 및 10분까지 남은 시간

Streamlit 화면은 기존 `@st.fragment(run_every="2s")` 작업 큐를 유지한다. 화면 갱신 때문에 AI 호출이나 토큰을 추가로 사용하지 않는다. 완료율을 추정하지 않고, 실제 단계와 실제 경과 시간만 보여준다.

## 필수 테스트

1. 일반 캐시 미스 작업에서도 Codex 호출이 정확히 1회인지 확인한다.
2. 공통 학습가이드 캐시는 계속 재사용되고, 이번 수업 족첵·써머리에 `analyze_source()`가 호출되지 않는지 확인한다.
3. 텍스트가 충분한 PDF는 시각 렌더링을 하지 않는지 확인한다.
4. 텍스트가 부족한 PDF는 해당 페이지만 `visual_required`로 전달하는지 확인한다.
5. 선택 강의자료가 있으면 페이지 기준은 강의자료, 제목은 족첵 메타데이터를 따르는 기존 규칙을 유지하는지 확인한다.
6. 같은 입력의 완성 노트 캐시는 Codex를 0회 호출하는지 확인한다.
7. fake runner로 deadline을 넘겼을 때 10분 전에 간이 노트가 생성되는지 짧은 테스트 시간으로 확인한다.
8. 4건 동시 제출 시 한 작업이 여러 Codex 슬롯을 독점하지 않는지 확인한다.
9. 기존 전체 테스트를 통과한 뒤 실제 대표 자료 4건을 동시에 제출해 제출→HTML 및 제출→Drive 시간을 기록한다.

## 완료 기준

- 최근 대표 자료 4건을 동시에 제출했을 때 첫 3건의 중앙값이 5분 이하이다.
- 네 번째 작업을 포함한 모든 작업이 10분 이내에 HTML 결과 또는 명시적인 간이 노트를 제공한다.
- 단일 일반 작업의 Codex 호출 수가 1회 이하이다.
- 동일 입력 재실행은 완성 노트 캐시로 AI 호출 없이 완료된다.
- 기존 제목, 페이지 기준, 과목별 Drive 폴더, 사용 자료 표기와 HTML UI가 유지된다.
- API 키와 OpenAI API 사용이 추가되지 않는다.
